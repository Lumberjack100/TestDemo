# release 技能需求文档

## 目标

请你创建一个名为"release"的技能，用于版本发布。

## 第一步. 更新 changelog.md

根据 Git 历史记录，将最新的变更内容更新到 `changelog.md` 文件中。

**执行步骤：**

1.  **读取 `changelog.md`**：读取文件内容，找到顶部列出的最新版本号（例如 `5.5.2`）。
2.  **确定 Git Tag**：构建该版本对应的 Git Tag。格式为 `V<version>`（例如：如果版本是 `5.5.2`，则 Tag 为 `V5.5.2`）。
    - 注意：请使用 `git tag -l V<version>` 命令验证该 Tag 是否存在。
3.  **获取 Git 日志**：获取从该 Tag 到当前 `HEAD` 之间的提交记录。
    - 使用命令：`git log --no-merges --pretty=format:"%s" V<version>..HEAD`
    - 如果该 Tag 不存在，请搜索最近的一个 `V*` 格式的 Tag 并以其作为起点。
4.  **格式化并更新**：
    - 分析提交信息（Commit messages）。
    - 将其格式化为 Markdown 列表。
    - 在 `changelog.md` 的顶部添加一个新的版本章节。让用户确认：
        - 推断的版本号，例如 5.5.3
        - 提供其他版本号变更选项
    - 将更新后的内容写回 `changelog.md` 文件。

**示例条目格式：**
```markdown
## 5.5.3
### Feature/Module Name
- 提交信息 1
- 提交信息 2
```

## 第二步. commit 版本相关的 changelog 

## 第三步. 打上 Tag 并 push 到远程仓库
1. 使用第一步得到的版本号，打上 Tag
2. 用户确认后，push 到远程仓库

# release 技能迭代需求

## 目标

请你优化 `.claude/skills/release` 技能，同时支持发布预览版和正式版

### 发布预览版

1. 对应分支为 `fea_next`
2. 更新的是 `CHANGELOG_PREVIEW.md` 文件
3. Tag 格式为 `Tag_D_V<version>`

### 发布正式版

1. 对应分支为 `develop_v5.0`，如果当前处于 `fea_next` 分支，则需要先切换到 `develop_v5.0` 分支，然后合并 `fea_next` 分支到 `develop_v5.0` 分支
 - 切换分支以及合并分支时，必须经过用户确认
2. 更新的是 `CHANGELOG.md` 文件
3. Tag 格式为 `Tag_R_V<version>`
