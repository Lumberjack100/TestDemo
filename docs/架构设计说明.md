# mCloudapp_V5 架构设计说明

## 架构设计理念

### 1. 分层架构
项目采用经典的分层架构设计，自上而下分为：
- **表现层（Presentation Layer）**：UI界面和用户交互（`app`模块）
- **业务逻辑层（Business Logic Layer）**：处理业务规则和流程（ViewModel、UseCase）
- **数据访问层（Data Access Layer）**：数据存储和访问（`core_data`模块）
- **基础设施层（Infrastructure Layer）**：底层通信和工具支持（`core_commonlib`、`lib_ble`、`lib_network`等）

### 2. 模块化设计
- **高内聚低耦合**：每个模块功能独立，职责单一。
- **接口隔离**：模块间通过接口通信，降低依赖。
- **依赖倒置**：高层模块不依赖低层模块的具体实现，通过依赖注入（Koin）实现解耦。

### 3. MVVM架构模式
项目基于MVVM（Model-View-ViewModel）模式构建，并结合了Google推荐的架构组件。

```
View (Activity/Fragment) <-> ViewModel <-> Repository <-> DataSource
         ^                                                      |
         |                    LiveData/StateFlow               |
         +<----------------------------------------------------+
```

## 核心架构组件

### 1. 依赖注入框架 - Koin
项目使用Koin进行依赖注入，管理ViewModel、Repository和各类服务实例的生命周期。

#### 模块组织
Koin模块按功能和分层进行组织，在`app`模块的`AppKoinModule.kt`中进行聚合。

```kotlin
// docs/../app/src/main/java/com/shmedo/mcloudapp/koin/AppKoinModule.kt
val appKoinModule = module {
    includes(
        coreKoinModule,
        deviceBaseKoinModule,
        viewModelModule,
        bleKoinModule,
        locationKoinModule,
        tcpKoinModule
    )
}
```

#### ViewModel模块定义
`ViewModelModule.kt`专门负责所有ViewModel的注入。

```kotlin
// docs/../app/src/main/java/com/shmedo/mcloudapp/koin/ViewModelModule.kt
val viewModelModule = module {
```

### 2. 数据流架构 - StateFlow & LiveData
项目采用`StateFlow`和`LiveData`作为ViewModel和View之间通信的桥梁，实现响应式UI编程和单向数据流。

### 3. Repository模式
数据仓库层（Repository）是数据访问的统一入口，负责协调本地数据源和远程数据源。

#### Repository实现示例
`NetDataRepository`负责处理所有与后端API相关的网络请求。

```kotlin
// docs/../core_data/src/main/java/com/shmedo/core/data/repository/NetDataRepository.kt
class NetDataRepository private constructor() {

    /**
     * 通过token获取用户基本信息
     */
    suspend fun getUserByToken(onCatch: ((Throwable) -> Unit)? = null): BasicUserInfo? =
        RxHttp.get("/GetUserByToken")
            .setDomainIfAbsent(BaseURL.AUTHORITY_SERVICE_ADDRESS.baseUrl)
            .addHeader("Authorization", AuthMMKVOwner.token)
            .toAwaitResponse<BasicUserInfo>()
            .tryAwait(onCatch)
            
    /**
     * 查询设备详细信息
     */
    suspend fun getDeviceDetailInfo(
        jsonParam: String,
        onCatch: ((Throwable) -> Unit)? = null
    ): DeviceDetailInfo? =
        RxHttp.postJson("/GetDeviceDetail")
            .setDomainIfAbsent(BaseURL.IOT_MANAGER_SERVICE_ADDRESS.baseUrl)
            .addHeader("Authorization", AuthMMKVOwner.token)
            .addAll(jsonParam)
            .toAwaitResponse<DeviceDetailInfo>()
            .tryAwait(onCatch)
            
    companion object {
        val instance = NetDataRepository()
    }
}
```

## 通信架构

### 1. 蓝牙通信架构
`lib_ble`模块封装了蓝牙通信能力，基于`Nordic BLE`库实现。


### 2. 网络通信架构
`lib_network`模块基于`RxHttp`和`OkHttp`封装了HTTP网络请求能力。

#### 网络层次结构
```
应用层 -> RxHttp封装层 -> OkHttp核心层 -> Socket层
```

#### 请求示例
```kotlin
// 在Repository中使用RxHttp发起请求
suspend fun loginByAccount(
    jsonParam: String,
    onCatch: ((Throwable) -> Unit)? = null
): String? =
    RxHttp.postJson("/SignIn")
        .setDomainIfAbsent(BaseURL.AUTHORITY_SERVICE_ADDRESS.baseUrl)
        .addHeader("access_type", "android")
        .addAll(jsonParam)
        .toAwaitResponse<String>()
        .tryAwait(onCatch)
```

### 3. TCP通信架构
`lib_tcp`模块使用`Netty`实现了TCP长连接通信。

#### Netty客户端架构
```
ChannelPipeline
├── IdleStateHandler (心跳检测)
├── MessageDecoder (消息解码)
├── MessageEncoder (消息编码)
└── BusinessHandler (业务处理)
```

## 数据存储架构

### 1. Room数据库
项目使用Room持久化库进行本地数据存储，如用户信息、设备列表等。数据库定义见`core_data`模块。

### 2. MMKV键值存储
对于少量、频繁读写的配置信息和用户凭证，项目使用`MMKV`以获得更好的性能。

#### 封装使用
`core_commonlib`中的`MmkvCacheUtil`提供了统一的MMKV访问入口。

#### BaseVmDbActivity
`BaseVmDbActivity`定义了View初始化、数据加载和事件观察的核心流程。

```kotlin
// docs/../app/src/main/java/com/shmedo/mcloudapp/ui/page/base/activity/BaseVmDbActivity.kt
abstract class BaseVmDbActivity : DataBindingActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        initView(savedInstanceState)
        initData()
        createObserver()
    }

    abstract fun initView(savedInstanceState: Bundle?)
    abstract fun initData()
    abstract fun createObserver()

    override fun isDebug(): Boolean {
        return false
    }
}
```

### 2. DataBinding
项目广泛使用DataBinding将UI组件与数据源绑定，减少了大量的`findViewById`和样板代码。

## 异步处理架构

### 1. Kotlin协程
项目全面拥抱协程来处理异步任务，包括网络请求、数据库操作和耗时计算。

#### ViewModel中的协程
```kotlin
// 示例
class LoginViewModel : ViewModel() {
    fun login(account: String, pass: String) {
        viewModelScope.launch {
            // 在ViewModel的生命周期内启动协程
            val result = repository.loginByAccount(account, pass)
            // 更新UI State
            _loginState.value = result
        }
    }
}
```

### 2. 异常处理机制
网络请求等异步操作的异常通过`try-catch`或`RxHttp`提供的`tryAwait`进行捕获，并在ViewModel中转换为可供UI展示的错误状态。

## 性能优化架构

### 1. 内存优化
- **图片加载优化**：使用Glide进行图片缓存和内存管理
- **列表优化**：RecyclerView配合DiffUtil减少刷新开销
- **内存泄漏检测**：集成LeakCanary（Debug模式）

### 2. 网络优化
- **请求合并**：相同请求合并，避免重复
- **缓存策略**：合理设置HTTP缓存
- **数据压缩**：启用GZIP压缩

### 3. 启动优化
- **延迟初始化**：非必要组件延迟加载
- **异步初始化**：耗时操作异步处理
- **启动任务优先级**：按优先级初始化组件

## 安全架构

### 1. 数据安全
- **敏感数据加密**：使用AES加密存储
- **网络传输加密**：HTTPS + 自定义加密
- **代码混淆**：ProGuard/R8混淆

### 2. 权限管理
- **动态权限申请**：使用XXPermissions框架
- **权限最小化原则**：只申请必要权限
- **权限说明**：向用户说明权限用途

## 总结

mCloudapp_V5的架构设计遵循了现代Android开发的最佳实践，通过分层架构、模块化设计、MVVM模式和依赖注入等手段，实现了高内聚低耦合的代码结构。整体架构具有良好的可扩展性、可维护性和可测试性，为项目的长期发展奠定了坚实的基础。
